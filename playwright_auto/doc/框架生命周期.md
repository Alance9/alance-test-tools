# Alance UI 自动化测试框架

基于 **Pytest + Playwright（同步 API）+ Allure** 的高度封装 Web UI 自动化测试框架，采用 POM（Page Object Model）设计，覆盖被测平台 [Alance 测试工具平台](https://alance9.pythonanywhere.com/) 的邀请码门禁及 10 个工具菜单。

- 被测站点：`https://alance9.pythonanywhere.com/`
- 邀请码：`alan`
- 运行环境：Windows / Python 3.9+
- 当前结果：**61 passed, 1 skipped**（skip 项为服务端缺少 pycryptodome 的 AES 用例，框架自动跳过）

### 分层设计

| 层 | 目录 | 职责 |
|---|---|---|
| 配置层 | `config/` | 所有环境相关参数集中管理，支持 `.env` 覆盖 |
| 元素仓库 | `locators/` | 选择器、Tab/按钮文案、业务枚举全部 YAML 化，运行时一次性加载缓存 |
| 基础层 | `common/` | `BasePage` 封装 Playwright 原语，自动等待 + Allure 步骤 + 日志 |
| 页面对象层 | `pages/` | 每个页面/菜单一个类，只表达“做什么”，不写选择器字面量 |
| 用例层 | `tests/` | 仅调用 POM 的业务方法 + 断言，含 Allure epic/feature/story/title |

## 二、环境准备（首次运行）

> 以下命令在 **PowerShell** 中执行，工作目录为项目根目录 `e:\Code\AITest\autoUiPw`。

### 1. 创建并激活虚拟环境

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. 安装 Python 依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3. 安装 Playwright 浏览器

本框架将浏览器安装在**项目内** `.ms-playwright`（由 `settings.py` 通过
`PLAYWRIGHT_BROWSERS_PATH` 指定），不污染用户目录：

```powershell
# 设置浏览器安装目录（当前窗口生效）
$env:PLAYWRIGHT_BROWSERS_PATH="e:\Code\AITest\autoUiPw\.ms-playwright"
# 安装 Chromium（headless 模式另需 headless-shell，install 命令会一并处理）
.\.venv\Scripts\python.exe -m playwright install chromium
```

### 4. 安装 Allure 命令行（生成 HTML 报告用）

需 JDK 8+，任选一种方式：

```powershell
# 方式一：Scoop
scoop install allure

# 方式二：手动下载 https://github.com/allure-framework/allure2/releases
#         解压后将 bin 目录加入 PATH
```

未安装 Allure CLI 不影响测试执行，只是最后一步改为手动查看
`reports/allure-results`。

### 5.（可选）自定义环境配置

```powershell
Copy-Item .env.example .env
```

按需修改 `.env` 中的站点地址、邀请码、是否无头、慢放毫秒等；`.env` 优先级高于代码默认值。

## 三、自动化运行步骤

### 方式一：批处理一键运行（推荐）

```powershell
.\run.bat                  # 无头执行全部用例，并生成 Allure 静态报告
.\run.bat --headed         # 有头模式，可实时观察浏览器操作
.\run.bat --serve          # 执行完成后自动启动服务并在浏览器打开报告
.\run.bat -m menu1         # 透传任意 pytest 参数（只跑菜单01）
```

### 方式二：Python 入口

```powershell
.\.venv\Scripts\python.exe run.py
.\.venv\Scripts\python.exe run.py --headed --serve
```

### 方式三：直接使用 pytest

```powershell
# 新开 PowerShell 窗口时需先指定项目内浏览器目录
$env:PLAYWRIGHT_BROWSERS_PATH="e:\Code\AITest\autoUiPw\.ms-playwright"

.\.venv\Scripts\python.exe -m pytest                      # 全量执行
.\.venv\Scripts\python.exe -m pytest tests/test_07_crypto.py   # 执行单个文件
.\.venv\Scripts\python.exe -m pytest -m menu2             # 按标记执行（菜单02）
.\.venv\Scripts\python.exe -m pytest -k "base64"          # 按用例名关键字执行
.\.venv\Scripts\python.exe -m pytest --headed             # 有头模式
```

可用的自定义标记：`smoke`、`menu1` ~ `menu10`（定义见 `pytest.ini`）。

### 生成与查看 Allure 报告

```powershell
# 用例执行后由 pytest 自动产出原始结果到 reports/allure-results

# 生成静态报告到 reports/allure-report
allure generate reports/allure-results -o reports/allure-report --clean

# 本地起服务直接在浏览器查看（二选一）
allure serve reports/allure-results
allure open reports/allure-report -p 8899
```

报告内含：用例通过率、按菜单（feature）/场景（story）分组、
每步操作日志、失败用例的全页截图与失败时 URL。

## 四、框架关键约定

1. **门禁免重复输入**：除 `test_00_gate.py` 专项验证门禁外，其余用例由
   `conftest.py` 通过 `add_init_script` 预置 sessionStorage 标记
   `alance_invite_passed=1`，直接进入工具页。
2. **工具页在 iframe 内**：首页点击菜单后加载 `iframe#toolFrame`
   （src 为 `/t/<key>/`），`HomePage.open_tool()` 已封装 frame 等待与竞态处理。
3. **智能等待**：页面大量操作为异步 fetch（加载示例、分析、搜索、生成、加解密），
   `BasePage` 提供 `wait_result_success` / `wait_result_nonempty` /
   `wait_input_value` 等条件等待，用例中不写固定 `sleep`。
4. **失败自动截图**：任意用例失败时自动全页截图，挂入 Allure 附件并存盘
   `reports/screenshots/`。
5. **Toast 捕获**：通过注入 MutationObserver 预先监听动态 `#toast` 节点，
   规避其仅存活约 2 秒导致的断言不稳定。
6. **测试图片零依赖**：图片类用例所需 PNG 由 `conftest.py` 用标准库
   `zlib + struct` 手写生成（`data/sample_120x80.png`），无需 Pillow。

### YAML 元素仓库（元素与代码分离）

所有页面元素统一维护在 `locators/<模块名>.yaml`，POM 代码中不再出现选择器字面量：

```yaml
# locators/text.yaml
tabs:                          # Tab 文案：业务 key -> 页面中文文案
  text_compare: "文本对比"
buttons:                       # 按钮文案：业务 key -> 按钮可见文本
  start_compare: "开始对比"
selectors:                     # 选择器：业务 key -> CSS（支持 {占位符} 模板）
  compare_input_a: "#textCompareA"
  field_value: "#val_{name}"   # 动态 id，调用时传模板变量
stat_ids: {}                   # 其他业务枚举段（名称按需自定义）
```

- **一次加载、全局缓存**：会话开始时由 conftest 的 `_preload_locators`
  调用 `locator_loader.load_all()` 扫描并加载全部 YAML，之后整个运行周期只读盘
  一次，所有页面共享内存缓存（首次访问也会惰性兜底加载）。
- **POM 使用方式**：页面类声明 `LOCATOR_MODULE = "text"` 后即可按 key 操作：

| BasePage 方法 | 作用 |
|---|---|
| `self.el("compare_input_a")` | 按 key 取 Locator |
| `self.el("field_value", name="姓名")` | 模板选择器传参（`#val_姓名`） |
| `self.sel("xxx")` / `self.id_of("xxx")` | 取选择器字符串 / 取纯元素 id |
| `self.fill_el("img_width", 100)` | 按 key 定位输入框并填充 |
| `self.select_el("img_fmt", label="PNG")` | 按 key 定位下拉框选择 |
| `self.upload_el("crop_file", path)` | 按 key 定位上传控件 |
| `self.click_btn("start_compare")` | 按 buttons key 点击按钮 |
| `self.switch_tab_by_key("text_compare")` | 按 tabs key 切换 Tab |
| `self.common_sel("code_box")` | 取 common.yaml 跨页通用选择器 |

- 跨页面共享的骨架元素（Tab 栏、激活面板、单/复选框、代码块）放在 `locators/common.yaml`。
- 页面元素变更时**只改 YAML 不改代码**；新增自定义枚举段（如 `stat_ids`、
  `char_types`）后用 `locator_loader.section(module, "段名")` 读取。

## 五、添加新用例 / 新页面

1. **先维护元素**：在 `locators/<模块>.yaml` 的 `tabs / buttons / selectors`
   段登记新元素（动态元素用 `{占位符}` 模板）；
2. **编写页面方法**：在 `pages/` 对应页面对象（继承 `BasePage`，声明
   `LOCATOR_MODULE`）中通过 `el / fill_el / click_btn / switch_tab_by_key`
   等 key 方式操作，并加函数级注释；
3. **编写用例**：在 `tests/` 对应 `test_XX_*.py` 中通过
   `open_tool(key, PageClass)` 工厂获取 POM，用 `@allure.story`、
   `@allure.title` 标注场景，断言只校验业务结果。

```python
@allure.story("Base64")
@allure.title("Base64 编码与解码可逆")
def test_base64_roundtrip(self, tool):
    encoded = tool.base64_encode("Alance2026")
    assert encoded == "QWxhbmNlMjAyNg=="
```

## 六、常见问题

| 现象 | 原因与处理 |
|---|---|
| 提示找不到浏览器 | 新终端窗口需重新设置 `$env:PLAYWRIGHT_BROWSERS_PATH` 指向项目内 `.ms-playwright` |
| AES 用例显示 skipped | 被测服务端未安装 pycryptodome（页面有明确提示），属服务端环境限制，非框架问题 |
| 命令末尾出现 `TRAE Sandbox Error` | 沙箱拦截搜狗输入法日志/浏览器缓存写入，pytest 已正常产出 PASSED 即不影响结果 |
| PowerShell 无法执行脚本策略 | 执行 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| 端口 8899 被占用 | `allure open` 时更换 `-p` 端口号即可 |
